# Project memory

Durable decisions and lessons that the code and docs don't record. Imported by `CLAUDE.md`. Add an entry when a decision is made or a lesson is learned; remove entries that stop being true.

## Decisions

- **Batch API (Sprint 7).** A failed dataset is returned as its exception in place, never raised, so the others complete. One `column=` applies to the whole batch. Python validates each dataset first; a dataset that fails there becomes its exception. One indicator per batch call; mixed-indicator batches come in a later sprint.
- **Tokio vs Rayon.** Tokio is not used per request. Benchmarks (full run, 2026-10-27) showed Rayon `par_iter` up to 10x faster than a Tokio task per request, chunking added nothing, and a Tokio one-hop wrapper cost a fixed ~10-15 µs. Rayon owns scheduling; Tokio is only the async front door (`execute_batch`) for a future async API.
- **Fork safety.** The bridge uses its own Rayon pool tied to the process id and rebuilds it in a forked child (the stale pool is leaked on purpose). Do not use Rayon's global pool from the bridge.
- **Input magnitude limit (2026-10-28).** `Series` rejects finite values above `MAX_ABS_INPUT` (`1e290`, `pyta-common`) as `ValueOutOfRange`, rather than making kernels overflow-safe: SMA's window sum and RSI's price change overflowed near `f64::MAX`, and the limit keeps every sum of up to 2^60 values finite at zero cost (same compare as the finiteness check). A kernel that squares values must scale or centre first.
- **Sprint 9 design (2026-10-28).** CCI (Momentum; high, low, close) is the first multi-column indicator and proves the contract; ATR waits for the Volatility category (Sprint 11.5). Rust takes multi-column input as a generic `Columns` type (equal-length validated `Series` in the indicator's slot order), with `IndicatorRequest.input` either a `Series` or `Columns`; the fixed five-column `Ohlcv` struct is removed, so fundamental roles need no new Rust type. Built 2026-10-28: `IndicatorInput::{Series, Columns}`; `PytaError::InvalidOhlcv` was removed with `Ohlcv` and `ColumnCount` added for a request of the wrong shape.
- **Row checks across columns live in Python (2026-10-28, user's decision).** High below low on any row is a `ValueError` raised by Python (`ORDERED_ROLES` in `_columns.py`), naming both columns and the row in the caller's numbering; Rust does not check it. Equal high and low is valid. CCI accepts `period=1` (all 0) although TA-Lib rejects it, so the shared period validator stays generic.
- **Multi-column value checks are lazy (2026-10-28).** Rust already rejects non-finite and too-large values, so for multi-column input Python scans values only after a native `ValueError`, to name the column and row; scanning every column upfront, plus uncached name matching, made a 100-row CCI call cost ~36 µs in Python against ~15 µs now.
- **Integration project (2026-10-30, Sprint 12, user chose the location).** `PyTA-Integration/` in the repo root: own `pyproject.toml` (`[tool.uv] package = false`, no `uv.lock`, since `pyta` is a locally built wheel), own `.venv`; `scripts/setup.sh [--bench] [--no-build] [--no-run]` builds the release wheel from the root `pyproject.toml` (`maturin build --release --out PyTA-Integration/dist`; `--manifest-path` alone would miss `python-source`), installs it with `uv pip install <wheel> -r pyproject.toml --group dev`, runs examples, pytest and ruff. Root tooling never sees it (pytest `testpaths`, ruff/pyright paths). Its tests scan for `pyta._<private>` and `rust/crates` and assert `pyta` comes from site-packages via a wheel. Error-message tests match exactly, so a wording change in PyTA means updating them there. TA-Lib 0.8.3 is its `bench` extra only.
- **TA-Lib comparison (2026-10-30, Sprint 12).** `PyTA-Integration/benchmarks/compare_talib.py`: each library called as documented (TA-Lib one array/Series per input, PyTA a dict of named arrays or the whole DataFrame; TA-Lib batch = list comprehension, PyTA = `pyta.batch`), `timeit` best of 5 alternating, seeded random walk. Result (`docs/benchmarks/talib_comparison_2026-10-30.md`, README "Performance against TA-Lib"): TA-Lib faster in most cells; PyTA ahead only for large NumPy batches and ADX/Aroon/CCI. At 1M rows the native call itself is slower (OBV: `pyta._native.obv` 7.3 ms of an 8.2 ms call against TA-Lib's 3.6 ms), so it is not only the Python layer. Agreement within 8.7e-12 relative everywhere.
- **Planner refit (2026-10-30, Sprint 12 B4).** From the full `--batch --rust` run's break-even rows (`benchmark_2026-10-30_18-34-48`): SMA 1.8 → 1.5, WMA 2.7 → 1.9, STOCH 17.9 → 13.2, STDDEV 9.9 + 0.23·period → 5.1 + 0.21·period (period sweep 7.55 + 0.215·period ms at 1M rows). Break-even under the model is ~1.6 ns/element at 10 x 1,000, ~2.0 at 100 x 100, ~16 at 10 x 100. CCI left (its rows all choose right). Confirmed by per-indicator runs `_22-06-38` to `_22-49-03`.
- **Bit-parity policy (2026-10-30, user's decision, Sprint 12 B1).** Tolerance, not bits: PyTA promises agreement with TA-Lib 0.8.3 within 1e-9 (the fixture tolerance) and uses plain multiply-adds everywhere; no `f64::mul_add`, no runtime FMA dispatch. Bit-for-bit SAR/TRIX/EMA family would need per-function fused arithmetic plus CPU dispatch (`mul_add` without `+fma` is a libm call) for differences of at most 2.1e-12 relative (MACD near zero; EMA 2e-16, DEMA 4e-16, TEMA 1.2e-15, SAR 2.1e-16, TRIX 4e-13). Stated in `ARCHITECTURE.md` numerical conventions, `API.md` "Agreement with TA-Lib" and the wiki pages of EMA, DEMA, TEMA, MACD, KAMA, SAR, TRIX; `kernels::ema`'s doc no longer claims bit parity with 0.8.3.
- **Constants.** All tunables live in `pyta-common`. Planner costs were measured on a 16-thread i9-9900K and are machine-specific.
- **Per-indicator wiki.** `docs/indicators/` is reserved for user-facing docs: one folder per category, one page per indicator (what it is, what it is for, how to use it). Every category folder has a `README.md` index (indicator, inputs, outputs); add a page and a row there with every new indicator (momentum and trend indexes added 2026-10-30 at the user's request).
- **Default column.** Each indicator function chooses the column role it calculates on and passes it as `default_column` (`CLOSE` for SMA and RSI); `_validation.py` has no default of its own. An explicit `column=` must be a standard role name or alias (so user code reads the same on every data source; "standards are standard for a reason") and present in the input, else it is an error, but with no `column=` a lone column is used whatever its name (this is what lets indicator outputs chain). Aliases are matched per role, never across roles: `close` does not fall back to `adj_close`.
- **Planner refit (2026-10-27).** The few-request workloads (3/5/10 requests) were added and the constants were not changed: a fit over 82 rows found no better set, and the 3 remaining misses at 3,000 points cost under 7 µs each. Do not re-chase them without new data or a model with a per-element term.
- **Multi-column indicators.** Roles are found by name automatically. The override is `columns=[...]` (not a dict): order does not matter, each name is assigned to the indicator's slot for its role (slots are per indicator and may accept several roles, such as `close` or `adj_close`). Unrecognized names, duplicate roles and missing slots raise. Unnamed 2-D arrays and tuples use the documented order. From 2026-10-29 (maintainer's decision) a 2-D table (array, list of lists, JSON array of arrays) may be `(rows, columns)` or `(columns, rows)`: the axis equal to the slot count is the columns, `(rows, columns)` when both are; a list or tuple of Series is matched by name when every one is named by a role, else taken in order, and must share one index. `column=` is single-column only, `columns=` multi-column only. Optional-`period` defaults were considered and dropped for the MVP (SMA has no standard period); RSI keeps 14.
- **CI.** `ci.yml` stays basic until Sprint 13, so leave that Sprint 13 task unchecked.
- **Context7 budget (2026-10-28).** The Free account has 1000 requests a month, then 20 bonus calls a day until the reset (reset assumed on the 1st; it may be the 28th, the account's creation day; change `reset_day` in `~/.claude/context7/config.json` once known). The skill is global (`~/.claude/skills/context7-budget`) and its hooks are in `~/.claude/settings.json`, so calls from every project are logged to `~/.claude/context7/usage.jsonl`; they block at 15 calls per session, or when the month and the day's bonus are both spent. Subagent calls carry the parent's session id, so they share that cap (the user chose one cap per session, not per agent); the ledger records each call's agent type. Calls from other machines are not counted, so `sync` from the dashboard now and then.
- **Skills layout (2026-10-28).** General skills are global in `~/.claude/skills/` (`context7-budget`, `lsp-navigation`, `cpp-development`, `ue5-development`, `format-on-edit`, `orchestrator`), and global agent roles (`researcher`, `implementer`, `reviewer`, `tester`) are in `~/.claude/agents/`, used by default (`pyta-tooling` has the PyTA rules for them). `format-on-edit` is a global PostToolUse hook on Write/Edit: final newline for every text file, rustfmt on `.rs`, ruff format on `.py`. Each project gets one project-level skill naming which of them and which MCP servers apply (`pyta-tooling` here); `CLAUDE.md` only points to it.
- **Adding indicators (2026-10-28).** The `add-indicator` skill is the procedure. When sources disagree on a formula, TA-Lib's convention wins (document differences from the original author). Indicators that need more input columns, extra parameters or several outputs extend the engine contracts generically as part of the work, designed in the spec the user approves; the spec is the only checkpoint. Cost constants come from a quick benchmark scaled against RSI, confirmed later by a full run.
- **TA-Lib differential testing (partly settled, 2026-10-28).** From Sprint 10, reference fixtures may be generated by TA-Lib itself (PyPI `TA-Lib`, wheels bundle the C library) in a throwaway env, like the yfinance data, citing the version and compared exactly; TA-Lib never becomes a dependency. A standing differential job (CI or scratch env over every indicator) is still to be decided during QA. Older fixtures come from cited published examples.
- **Sprint 10 design (2026-10-28, user's decisions).** Parameters are per indicator: `period=` for SMA, RSI, CCI, EMA (default 30, `period=1` allowed and an exact copy, though TA-Lib rejects it); `fast=`, `slow=`, `signal=` for MACD; Rust carries them as a `Params` enum with one variant per indicator. EMA ships as a full indicator. MACD's minimum input is `slow + signal - 1`, so every output has a value; its kernel is one fused pass, bit-identical to separate TA-Lib-style EMA passes and 2.1-2.3x faster (A/B 2026-10-28). MACD follows TA-Lib: both EMAs start at `slow - 1`, `slow < fast` is swapped silently (TA-Lib and pandas-ta do; Tulip rejects), ranges fast/slow ≥ 2, signal ≥ 1; each output keeps its own warm-up (`macd` from `slow - 1`, signal and hist from `slow + signal - 2`), unlike TA-Lib's common one. Output names are bare (`sma`, `rsi`, `cci`, `macd`, `macd_signal`, `macd_hist`), no parameters, for every indicator. Casing follows the input's OHLCV columns: lower → lower; upper → upper; title (yfinance) → abbreviations upper, words title (`SMA`, `MACD_Signal`); separator `_`; mixed or unnamed → lower. A word in capitals counts as title-compatible (`MACD_Signal`, `SPY Close`), so PyTA's own title-case outputs chain as title (orchestrator's call during the sprint, for the user to confirm). One-series input to a multi-output indicator returns a tuple of outputs in documented order.
- **Sprint 11.5 design (2026-10-29, user approved every recommendation in `TODO.md` Part A).** Formula rule: a professional standard where one exists, else TA-Lib; research found no formal standard for any of the 24 indicators (only original authors, whom TA-Lib follows), so TA-Lib's calculation rules. Reference: the TA-Lib release bundled in the PyPI wheel, 0.8.3 conventions where they differ (0.8.3, 2026-10-25, changed flat-window guards in STOCH/MFI/ULTOSC/WILLR, BBANDS' default to 20, and the variance algorithm), version cited in each fixture. Defaults are TA-Lib's except Stochastic 14/3/3 (TA-Lib 5/3/3); no-TA-Lib ones: Ichimoku 9/26/52, Keltner 20/10/2.0, Donchian 20, CMF 20. Zero denominators follow TA-Lib (flat STOCH/WILLR → 0, empty MFI → 0, zero-TR ULTOSC term dropped, ROC zero base → 0, A/D and CMF high == low add 0); VWAP/CMF with zero volume → NaN. Each output keeps its own warm-up. SMA only (no `matype`). Ichimoku unshifted, five outputs (a `shift` option was added 2026-10-30; see the Ichimoku entry). Keltner modern (EMA(close) ± k·Wilder ATR). Donchian includes the current row. VWAP typical price, cumulative from row 0. Population std dev with a stable centred kernel. Python rejects ULTOSC periods out of order and SAR `acceleration > maximum` instead of reordering/clamping; negative volume is a row error. Output order natural (`aroon_up` before `aroon_down`, unlike TA-Lib). Shared kernels live in `pyta-core` because category crates cannot depend on each other.
- **Sprint 11.5 infrastructure B2-B4 (2026-10-29, implementer's calls for review).** `Params` derives `PartialEq` only (no `Eq`/`Hash`), so fields may be `f64`; nothing relied on `Eq`. `PytaError::InvalidParameter` holds `usize`, so the first float-parameter kernel needs its own `pyta-core` error variant. Shared Python validators: `validate_positive_float(name, value, maximum=None)` (finite, > 0, ints converted, bool `TypeError`, plain-float fast path), `validate_ascending(*(name, value), strict)` for SAR (`strict=False`) and ULTOSC (`strict=True`), and `validate_int(name, value, minimum)` for named ints. Runners take `params: tuple[int | float, ...]`, `()` for parameterless indicators. Negative volume: `NONNEGATIVE_ROLES = ("volume",)` in `_columns.py`, checked eagerly (Rust accepts negative values, so it cannot be lazy) inline in `_api._trim_columns` for multi-column input only; a shared `check_rows` call cost ~0.2 µs (+1.5%) on a 100-row CCI dict call, the inline membership test measured within noise (0.996-1.016 over three interleaved runs). Single-column input matched to the `volume` role is checked too since Volume ROC (see its entry). `volatility` and `volume` exist as empty categories (crates, namespaces, docs `README.md`) ahead of their first indicators.
- **Shared kernels, B1 (2026-10-29, implementer's calls kept).** `pyta_core::kernels` holds the building blocks every category uses (EMA, Wilder average and sum, true range, rolling extremes, typical price, rolling mean/std, compensated sums, `is_zero_scaled` = TA-Lib 0.8.3's `TA_IS_ZERO_SCALED`, `ZERO_TOLERANCE` 1e-14 in `pyta-common`). Rolling extremes use the van Herk/Gil-Werman block algorithm, not a monotonic deque: on 1e6 random-walk rows it took 3.1/2.6 ms at period 14/200 against 13.2/12.0 for `VecDeque` (ties go to the newest row, as Aroon needs). MACD keeps its fused loop, built from `ema_step`. `WilderAverage` uses RSI's form `avg*(n-1)/n + x/n`, not TA-Lib's `(prev*(n-1)+x)/n`; ATR differs from TA-Lib in the last bit only, inside the 1e-9 tolerance. Rolling std is two-pass per window (O(n·p), rescaled when squares would overflow); a flat window gives ~1e-16 of its magnitude, not exactly 0. EMA, MACD, RSI, CCI stayed bit-identical (hash over 300 calls).
- **STDDEV and float parameters (2026-10-29, implementer's calls for review).** A flat window reads exactly 0, as TA-Lib's does: a deviation within `is_zero_scaled(std, |mean|)` (1e-14 of the window's level, far below a real tick: 1e-8 on 100 is 1e-10) is snapped, costing no more than run noise. `PytaError::InvalidFloatParameter { name, value }` (message "{name} must be a finite number greater than 0, got {value}") is the float-parameter error; STDDEV's `period < 2` (0 included) is `InvalidParameter { name: "period", minimum: 2 }`, not `InvalidPeriod`, and `period > length` is `PeriodExceedsLength` as for SMA. A `k` so large that `k * std` overflows gives `inf` (not rejected). Fixture `# k: 2.0` comments are read by `Reference::float_parameter` (Rust) and as floats in `Reference.parameters` (Python).
- **BBANDS (2026-10-29, implementer's calls for review).** One `rolling_mean_std` pass: the means are the middle band and the deviation buffer is reused as the upper band, so only the lower band is a new allocation. The flat-window snap lives once, in `pyta-volatility`'s private `deviation::scaled_deviation(deviation, mean, k)`, used by STDDEV and BBANDS (STDDEV bit-identical). Errors as STDDEV (`InvalidParameter` for `period < 2`, `InvalidFloatParameter` for `k`, `PeriodExceedsLength`). One `k` for both bands (TA-Lib's `nbdevup`/`nbdevdn` and `matype` not exposed); TA-Lib accepts zero or negative `nbdev`, PyTA requires `k > 0`. Multi-output batch tests live in `test_bbands.py`, not `test_batch.py` (as MACD's), and `test_output.py` needed nothing (same shape as MACD).
- **Donchian Channels (2026-10-29, implementer's calls for review).** `donchian(high, low, period)`: `InvalidPeriod` for 0 and `PeriodExceedsLength` for `period > rows` (SMA/BBANDS' error, since it needs `period` rows, not ATR's `InsufficientData`). Middle is `(upper + lower) / 2` exactly as the fixture computes it, so all three outputs match bit for bit. Cost is one per-row constant (10.6 ns): the native sweep is flat from period 14 to 200 but ~17% higher at 5 and ~40% at 2 (one van Herk block per `period` rows); not modelled. `test_output.py` left on the `fake` stand-in: its multi-column cases are three-column OHLC tables, which a two-slot indicator rejects, so Stochastic (three columns, two outputs) remains the natural replacement.
- **Keltner Channels (2026-10-29, implementer's calls for review).** ATR's calculation moved verbatim into the crate-private `atr::atr_values(high, low, close, period)` (validated slices in, `Vec` out), which `atr` and `keltner` share, so Keltner's ATR is `pyta.atr`'s to the bit; the middle is `pyta_core::kernels::ema`. Bands are `middle ± k * atr` with `k * atr` computed once per row, which is the same IEEE result as NumPy's `ema + k * atr`, so the Python tests compare exactly. Errors: `InvalidPeriod` (period 0), `InvalidParameter { name: "atr_period", minimum: 1 }`, `InvalidFloatParameter` (`k`), `InsufficientData { required: max(period, atr_period + 1) }` (ATR's error, since the ATR needs `atr_period + 1` rows). The hand fixture's tolerance is 1e-9 because the exact fractions are not doubles and the Wilder form rounds in the last bit. Cost 11.3 ns/row (provisional): in the same quick run Keltner took 9.17 ms at 1,000,000 rows against 2.92 (EMA) + 4.47 (ATR) = 7.39 ms, the rest being the band pass and the lower band's allocation. Keltner is three columns and three outputs, so it could replace `test_output.py`'s `fake` stand-in now; left for Stochastic as `TODO.md` assigns.
- **WMA (2026-10-29, implementer's calls for review).** Kept in `pyta-trend` (no other sprint indicator needs a WMA kernel; Hull MA is parked). Drift control is TA-Lib's own: running plain and weighted sums (`weighted - plain + period * newest`, TA-Lib's order), rebuilt from the window every `8 * period` rows (`REBUILD_EVERY_PERIODS`, an algorithm constant in the kernel like SMA's rebuild, not in `pyta-common`), chosen over compensated sums because it costs ~1/8 of a window per row and reproduces TA-Lib's arithmetic; a proptest checks 100,000-row random walks against a direct per-window sum to 1e-9 of the window's magnitude. Errors as SMA (`InvalidPeriod`, `PeriodExceedsLength`); `period=1` is an exact copy as EMA; no 100,000 period cap (TA-Lib has one). Provisional cost 2.7 ns/row, no period term.
- **DEMA (2026-10-29, implementer's calls for review).** Fused one-pass kernel in `pyta-trend` (EMA1's warm-up values are kept in the output buffer only to seed EMA2, so no extra allocation), built from `ema_step`/`ema_multiplier`; a proptest checks it bit for bit against two `kernels::ema` passes (the second over `&ema1[period - 1..]`), and an A/B (scratch example, 1,000,000 rows, period 30, best of 30, three rounds, governor `performance`) took 3.47 ms fused against 8.07 ms cascaded (2.33x). TA-Lib 0.8.3 writes its EMA update as `fma(beta, prev, k * x)` with `beta = (n - 1) / (n + 1)`, not `(x - prev) * k + prev`; PyTA keeps the shared `ema_step` (the fma policy, 2026-10-30), so fixture values differ by at most 4e-16 relative (132 of 242 and 8 of 62 values bit-identical). Errors: `InvalidPeriod` for 0, `InsufficientData { required: 2 * period - 1 }` (saturating, as MACD's); `period=1` an exact copy (`-0.0` kept). Provisional cost 3.8 ns/row, no period term.
- **TEMA (2026-10-29, implementer's calls for review).** Same design as DEMA: one fused pass (EMA1 then EMA2 warm-up values kept in the output buffer to seed the next EMA), bit-identical to three `kernels::ema` passes (proptest, and the A/B checked 1,000,000 rows bit for bit), 3.60 ms against 11.35 ms cascaded (3.15x, same A/B method). Combination in TA-Lib's order, `EMA3 + (3 * EMA1 - 3 * EMA2)`. Fixtures within 1.2e-15 relative (TA-Lib's `fma` EMA form). Errors: `InvalidPeriod`, `InsufficientData { required: 3 * period - 2 }` (saturating). Provisional cost 4.3 ns/row, no period term.
- **KAMA (2026-10-29, implementer's calls for review).** Follows TA-Lib 0.8.3's `TA_KAMA` line by line (seed = previous close, rolling change sum subtract-then-add, `ER = 1` when the sum is `<= 0` or `<=` the *signed* net change, clamp to 1, flat-window reset after `period` exactly-zero changes; exact zero tests, so `is_zero_scaled` is not used). TA-Lib writes both multiply-adds as `fma`; PyTA uses plain arithmetic because `f64::mul_add` without `target-feature=+fma` is a libm call (kernel 7.39 ms against 3.39 ms at 1,000,000 rows), and the TA-Lib 0.8.3 wheel's fixtures still match bit for bit, so the wheel's build likely does not fuse them either. `period=1` is TA-Lib's explicit copy (output from row 0, one row needed), not the `period + 1` rows of the general case. No 100,000 period cap. Provisional cost 4.0 ns/row, no period term.
- **ADX (2026-10-29, implementer's calls for review).** TA-Lib 0.8.3's `TA_ADX` smooths with a precomputed `1 / period` (`sum - sum * inv + value`, `adx - (adx - dx) * inv`), not the older `sum - sum / period`: the divide form missed the 0.8.3 fixtures by up to 8.5e-16 relative, the multiply form matches all three outputs bit for bit, so the shared `WilderSum` (unused until ADX) was switched to the multiply form. Zero guards copied: DIs only when the TR sum is `> 0.0` (exact; else both 0, no DX), DX only when `+DI + -DI` is outside TA-Lib's fixed band `TA_IS_ZERO` (new `pyta_core::kernels::is_zero`, open interval `(-1e-14, 1e-14)`; not `is_zero_scaled`), a skipped DX leaves ADX unchanged and counts 0 in the first mean. `period < 2` is `InvalidParameter { name: "period", minimum: 2 }` (BBANDS' pattern), `InsufficientData { required: 2 * period }` saturating. One fused pass; provisional cost 10.6 ns/row, no period term.
- **Parabolic SAR (2026-10-29, implementer's calls for review).** Follows TA-Lib 0.8.3's `TA_SAR` line by line, including its first-row rules (direction from `TA_MINUS_DM` period 1, a tie long; row 1 clamps against itself). `acceleration > maximum` is a new `PytaError::ParametersOutOfOrder { lower, lower_value, upper, upper_value }` (message identical to `validate_ascending`'s non-strict one), generic over float pairs; ULTOSC later added a `strict` flag for its strict integer order. TA-Lib writes the step as `fma` and its wheel fuses it (`TA_FMA_MULTIVERSION`), unlike KAMA's: the approved spec's plain multiply-add misses the fixtures by one ulp on 8-33 of ~300 values (at most 2.1e-16 relative), `f64::mul_add` matched bit for bit at ~16% more kernel time; kept plain per the spec; settled by the fma policy (2026-10-30, see "Bit-parity policy"). Provisional cost 3.3 ns/row on the bench's sine input; the kernel is branch-bound, ~6 ms per 1,000,000 random-walk rows.
- **Aroon (2026-10-29, implementer's calls for review).** `aroon(high, low, period)` uses the shared `for_each_window_max`/`min` (van Herk, ties newest) with a window of `period + 1`, not TA-Lib's lazy rescan (O(n·period) on a falling high; the shared kernel was benchmarked against it in B1). Values are TA-Lib's expressions: up/down `factor * (period - (row - index))`, oscillator `factor * (highest - lowest)` (indices as exact `f64`), so both 0.8.3 fixtures match bit for bit. The highest-high row is parked in the oscillator buffer between the two walks (no extra allocation). `(100 / period) * period` is 100 ± 1 ulp for some periods (11, 22, 39, ... give 100.00000000000001, as TA-Lib; 97, 161, ... one ulp below). **Clamped (2026-10-30, user's decision, Sprint 12 B3):** up/down `.min(100.0)`, oscillator `.clamp(-100.0, 100.0)`, as RSI is clamped, so period 11's new extreme reads exactly 100; the below-100 periods are left (the range still holds). Proptest bounds are now exact; the period-14 fixtures are still bit for bit (the clamp never binds there). `InvalidParameter { minimum: 2 }`, `InsufficientData { required: period + 1 }` saturating; no 100,000 cap.
- **Stochastic (2026-10-29, implementer's calls for review).** `stoch(high, low, close, k, k_smooth, d)` in `pyta-momentum` follows TA-Lib 0.8.3's `TA_STOCH` with SMA and matches all three fixtures bit for bit (asserted in the Rust reference test). TA-Lib's SMA is a plain running total (add newest, divide by the period, subtract oldest), so it is a crate-private `talib_sma_into` in `stoch.rs`, not the shared compensated `rolling_mean` (which multiplies by `1 / period` and would erase %D's `4.5e-14` flat-stretch residue). Raw %K is parked in the `stoch_d` buffer (highest high from `for_each_window_max`, then the ratio in `for_each_window_min`), so the kernel allocates only its two outputs. `TA_STOCH` has no `fma`. A zero `k`, `k_smooth` or `d` is `InvalidParameter { name, minimum: 1 }` (not `InvalidPeriod` for `k`); `InsufficientData { required: k + k_smooth + d - 2 }` saturating. Title case is `Stoch_K` (`abbreviations=()`), unlike the old `fake` stand-in's `STOCH_K`. The `fake` shape in `test_output.py`/`test_roundtrip.py` is now `pyta.stoch(data, 3, 2, 2)`; `test_multi_output.py` keeps its fake runner tests. - **MFI (2026-10-29, implementer's calls for review).** `mfi(high, low, close, volume, period)` in `pyta-momentum` follows TA-Lib 0.8.3's `TA_MFI` line by line (scaled "unchanged" test, subtract-then-add running sums over a ring of `period` flows, null-run reset, clamped ratio, 0 for an empty window) and matches both fixtures bit for bit. A first version recomputed the leaving row's flow instead of keeping the ring: same bits but 14.2 ms per 1,000,000 rows against 8.4 ms with the ring (four typical-price divisions per row instead of one), so the ring stays. Price × volume is a product of two inputs and overflows near `MAX_ABS_INPUT`: the kernel tracks whether every total stayed finite and, if not, reruns with the volume scaled by an exact power of two (`overflow_scale`, largest product brought to ~2^960), which leaves every ratio bit for bit unless a flow becomes subnormal; no cost on ordinary data. TA-Lib has no such guard. `period < 2` is `InvalidParameter { minimum: 2 }`, `InsufficientData { required: period + 1 }`. Title case `MFI`. Provisional cost 10.0 ns/row. `bench_boundary.py` now passes the native call only its own columns (`[:width]`), which also fixes SAR and Donchian there (their native call got three arrays and raised `ColumnCount`).

- **A/D (2026-10-29, implementer's calls for review).** `ad(high, low, close, volume)` in `pyta-volume` follows TA-Lib 0.8.3's `TA_AD` and matches both fixtures bit for bit. Chaikin's multiplier is the crate-private `money_flow::money_flow_multiplier` (returns 0 when `high - low` is not above 0), and the kernel always adds `multiplier * volume`; that is TA-Lib's skipped add to the bit because the total starts at `+0.0` and round-to-nearest never makes it `-0.0`. - **CMF (2026-10-29, implementer's calls for review).** `cmf(high, low, close, volume, period)` in `pyta-volume`: TA-Lib has none, so StockCharts' definition with A/D's multiplier helper. Drift control is compensation, not periodic rebuilds: each row adds `two_sum(new, -leaving)` to a `CompensatedSum`, for the money-flow volumes (kept in a ring of `period`) and the volumes; a window is empty (→ `NaN`) when a count of its non-zero volumes is 0, so a rounding residue never decides it. `period > rows` is `PeriodExceedsLength` (needs `period` rows, as Donchian and WILLR). - **VWAP (2026-10-29, implementer's calls for review).** `vwap(high, low, close, volume)` in `pyta-volume`: typical-price VWAP cumulative from row 0, both sums compensated (a huge early volume does not swamp later small ones), `NaN` until the first non-zero volume. Overflow follows MFI: if the numerator sum ends non-finite (inf/NaN is absorbing in `CompensatedSum`), rerun with the volume scaled by a power of two; `overflow_scale` is duplicated from MFI because category crates cannot share code outside `pyta-core` (a candidate for `pyta_core::kernels` if a third user appears). No session reset (A9); the wiki's recipe is `df.groupby(df.index.date, group_keys=False).apply(pyta.vwap)`. Provisional cost 5.0 ns/row.

## Lessons

- **Benchmark harness bias.** All arms in `workloads.rs` must use the same Criterion harness (`iter_batched` with a clone made outside the timed section, results returned so they drop outside timing). A `sequential` arm on `iter_with_large_drop` looked 10-15% slower than identical code. In single-dataset workloads `auto/sequential` should read about 1.00x; if it doesn't, suspect the harness before the planner.
- Noise between runs is ~5%; the CPU governor is usually `powersave`, which adds variance (Sprint 10's A/B ran on `performance`).
- `cargo bench` needs `bench = false` on the `pyta-engine` library target, or Criterion flags such as `--noplot` hit the unit-test harness.
- **A/B beats old baselines (2026-10-28).** For a performance gate, benchmark `main` in a scratch worktree and the branch in the same session, alternating, rather than comparing with an old report: reports from different days differed by more than the effect being measured. The Sprint 7.5 logging gate (no `--single --python` baseline existed) ran both scripts twice each plus an interleaved best-of-5 `timeit`; single and batch calls were within ±0.6%.
- **Property tests find real bugs.** Hypothesis found RSI returning `100.00000000000001` when the average loss was negligible (`100 * gain / sum` rounds `100 * gain` first); the kernel now computes the ratio first. Proptest with ordinary magnitudes missed it, so keep a regression test for each such find.
- **maturin is a dev dependency (2026-10-28).** Build with `uv run maturin develop`, never `uv run --with maturin ...`: `--with` runs maturin in a throwaway overlay environment and `maturin develop` installs `pyta` there. Locally that went unnoticed because `uv sync` had already installed `pyta` editable into `.venv`; CI (`--no-install-project`) failed with `No module named 'pyta'`.
- **Cost constants near the crossover (2026-10-30, Sprint 11.5 close).** Scaling a kernel's 1,000,000-row time against RSI overstates cheap multi-column kernels, which are memory-bound there: A/D read 2.2 ns/row at 1M but 1.2-1.7 ns in the small batches where the planner's sequential/parallel break-even lies (~1.6-2.0 ns/element for 10 x 1,000 and 100 x 100 rows), so 2.1 ran them in parallel 1.8-1.9x slower. A constant only matters near that break-even: for a cheap kernel (under ~3 ns/row) check the full `--batch --rust` rows at 10 x 1,000 and 100 x 100 before changing it. Refit at close from the full run: ATR 6.2, STOCH 17.9, SAR 2.6, STDDEV per-row 9.9; A/D set to 1.5 from its batch rows; VROC kept at 1.5 (1.9 regressed 10 x 1,000 to 1.32x); SMA (+29%) and CCI (+25%) predate the sprint and were left, since their planner rows are fine. Check a tester's "no row above 1.10x" claim against the report's `<-- check` marks: one report said none where the full run had five.
- The Python layer costs ~3.4 µs per call regardless of size, which limits batch speedups on tiny series.
- **Per-call Python work shows at 100 rows (2026-10-28, Sprint 10).** Pydantic validation costs ~0.4 µs alone but ~1 µs inside a call, and closures, `str()` keys and extra frames built per call added ~0.3 µs (SMA) to ~2 µs (CCI): the first A/B was 8-16% slower than `main`. Plain in-range ints now skip Pydantic (same value; anything else still goes through it), and restores and casing lookups are built once per indicator. Measure a new per-call step with an interleaved `timeit` before keeping it.
